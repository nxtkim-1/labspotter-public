# LabSpotter documentation

Start with the product, then go as deep as you need.

## Use and demonstrate

- [Product guide](PRODUCT_GUIDE.md): suggestions, confirmations, observation notes, Projects, export, and recovery.
- [Demo walkthrough](../DEMO.md): an actual-flow film plan, with the scope labels that belong beside each scene.
- [Build evidence](BUILD_EVIDENCE.md): selected model, dated runtime checks, and what each check establishes.

## Run and inspect

- [Runbook](RUNBOOK.md): recorded environments, install commands, and recovery. Older sections are dated development records.
- [Wiring](../WIRING.md): API design and historical security/runtime checks. Read against the current server for account-mode and voice changes.
- [Saved-session design](SAVED_SESSIONS.md): original save/continue integrity model. Its single-owner-token description predates account-scoped hosting mode.
- [Private phone route](PRIVATE-PHONE-TAILSCALE.md): optional development setup, not a certified physical-phone test.

## Preserve the research record

- [Video-action measurements](VIDEO_ACTION_CHAIN.md): selected versus candidate heads and the correction to the earlier metrics table.
- [Development notes](DEVELOPMENT_NOTES.md): implementation history and provenance; some status statements are historical.
- [Development results](../DEV_RESULTS_1427.md): recorded model experiments.
- [Font provenance](FONT-PROVENANCE.md) and [third-party notices](../THIRD-PARTY-NOTICES.txt): asset origins and terms.

New user-facing documentation complements these records. It does not replace the experiments, corrections, or build history.
