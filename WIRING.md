# LabSpotter GUI <-> backend wiring (stage2, merged 2026-10-31, security-hardened 2026-10-31)

The GUI (gui/src, built to gui/dist) talks to server.py over HTTP. Localhost by default; optional same-Wi-Fi phone route.

## Security model (reviewed with backend owner, 2026-10-31)
- **Per-launch session token** protects every /api route except minimal health. server.py generates a random token each launch (or takes LABSPOTTER_TOKEN from the environment) and prints it once, only when stdout is an interactive terminal. The user types it into the GUI (Run tab); the GUI keeps it in memory only - never localStorage, never the URL, never in served HTML, never in logs. A LAN peer without the token gets 401 on every private route - authentication does not depend on network position.
- **The token is never served.** index.html and assets are served as-is (Cache-Control: no-store on index). A LAN peer fetching the page receives no secret.
- **Token never crosses origins.** The GUI binds the typed token to the endpoint origin it was entered for; switching endpoints never re-sends it - the new endpoint asks for its own token.
- **?api= links are proposals, never auto-adopted.** A ?api= URL shows a confirm bar naming the proposed backend ("Clips you upload and every run you open would go to that address"); nothing switches or persists until the user taps "Use this backend".
- **Host header validated** against the literal bind address + localhost (+ real local IPs when bound to 0.0.0.0). Unknown Host -> 403 on API and index alike (DNS-rebinding protection; the request's own Host is never used to authorize itself).
- **Origin allowlist** derived from those same literal hosts. Disallowed Origin -> 403 even with a valid token. Access-Control-Allow-Origin echoes the matched origin only - never *. Preflight (OPTIONS) only answers allowed origins, advertising exactly X-LabSpotter-Token and Content-Type.
- **Minimal public health**: GET /api/health without a token returns only {status, deps_ok, auth}. Head/encoder/version details require the token.
- **200 MB per-request upload cap kept**, and at most one upload/analysis at a time: concurrent POST /api/analyze gets an immediate 503 "busy - one upload/analysis at a time; retry in a moment" instead of piling body buffers in RAM. Static files are streamed in 64 KB chunks, not buffered whole. Remaining known tradeoff: the stdlib server still spawns a thread per connection, so a many-idle-connections flood is not bounded - acceptable for a local/trusted-Wi-Fi tool, not for public exposure (which is not authorized anyway).
- The 401/403 error bodies say only "session token required" / "unknown host" / "origin not allowed" - no token material, no stack traces.

## Contract (server.py implements all of it)
- GET  /api/health          -> open: {status, deps_ok, auth}; with token: adds {head, measured, encoder, deps, requires, status_labels}; deps.error present = encoder cannot load here
- POST /api/analyze?tag=T   -> [token] body = raw mp4 bytes (one clip: 4 s / 16 frames @ 4 fps, <=200 MB); -> {predictions, result}. Tags: [A-Za-z0-9][A-Za-z0-9_-]{0,63} - 400 otherwise (no dots/separators, so no path traversal). 409 {error} if the tag already exists: runs are NEVER overwritten (no approved overwrite flow); pick a new tag or remove runs/T on the host. 400 on missing/malformed Content-Length; 408 when the upload stalls (per-connection read timeout, LABSPOTTER_READ_TIMEOUT, default 30 s); 503 when another upload/analysis is in flight. Atomic publish: the pipeline writes into a hidden unique runs/.staging-<hex> dir (same filesystem), the server publishes by os.rename only after predictions/facts/result all exist AND parse, and re-checks tag existence under the pipeline lock at publish time - so no interleaving can overwrite or delete another request's run, failure removes only the request's own staging claim, a crash leftover never blocks the logical tag (stale .staging-* dirs are harmless - not API-visible, never tag-blocking; remove them manually only while every server on this package is stopped - there is deliberately no automatic sweep, which could delete another live server's active staging), and the staging dirs are unreachable over the API (invalid tag). Published artifacts and the response carry the requested tag, never the staging tag
- GET  /api/runs/T          -> [token] {predictions, facts, result} for a stored run; 404 {error: "no such run"}. Completion marker: a run exists only once result.json AND predictions.json were written, so an empty/partial dir is a 404, never an empty 200; malformed/truncated JSON in a run file -> clean 500 "run data unreadable on the backend host", never a handler crash or mixed-success render; realpath containment check on the run dir
- GET  /api/detections      -> [token] gui/detections.json (OWL-ViT boxes for the 8 recorded demo clips only, unvalidated)
- Static: gui/dist/* (open http://127.0.0.1:8765/ for the GUI served by the backend itself)

## GUI side
- Endpoint resolution: localStorage labspotter_api > the page's own origin (http://127.0.0.1:8765 when opened from a file or the hosted build). A ?api= param becomes a visible proposal only.
- First run shows a token field with the note "The launcher prints this token in its Terminal window each time it starts"; without it the panel says "Connected, locked" and analyze/load stay off. The token field hides again once a token is set.
- Analyze is DISABLED while /api/health reports deps.error (with a "Setup needed" note naming the missing modules) or while the backend is locked/unreachable - the GUI does not invite a known-failing call
- Run history: this-browser-only list in localStorage (key labspotter_history; tags + local open times + the endpoint each run came from, no secrets); a row from another endpoint is labeled and opens by switching the endpoint field openly; blocked/corrupt storage degrades to no-history without breaking the app; verbatim server errors on missing runs
- Server error bodies are shown verbatim in an "Analyze failed." / "Load run failed." box - no invented success
- Every server result is rendered as MODEL-PREDICTED, UNVALIDATED; gate UNVERIFIED; alert pending_review; approval NONE RECORDED
- Live Meta: the GUI has no Meta path; the chain refuses --live unless LABSPOTTER_LIVE_CLEARED=1 and MODEL_API_KEY are set (disabled in this build)

## Phone route (same Wi-Fi)
- server.py binds 127.0.0.1 by default. start-for-phone.command runs it with --host 0.0.0.0 (prints a trusted-network warning) and shows the iPhone URL http://<mac-ip>:8765/. Because the page and API share an origin there, no ?api= confirm is needed; the app asks for the session token, which is printed in the launcher Terminal window at startup - type it in once per launch. Token auth means anyone else on the Wi-Fi gets 401s, but treat the network as trusted anyway.
- VERIFICATION STATUS: the launcher's failure paths (missing python3 / missing packages / no Wi-Fi address detected) are tested and it never starts the server when a check fails; the --host bind, Host allowlist, LAN 401-without-token and 200-with-token are verified on Linux. It has NOT been run on a real Mac or reached from a real phone - dependency install on macOS, ipconfig behavior on real Wi-Fi, and phone reachability are unverified until tried on Thomas's machine.

## Saved sessions (BenchFreeze)
- `GET /api/bench/sessions` lists saved sessions on this backend (id, entry count, time, freeze status, integrity). `POST /api/bench/session/<id>/continue` re-verifies the hash chain and the freeze checkpoint hash and returns the saved record. Both need the owner token (X-LabSpotter-Token) plus the Host and Origin checks, and neither returns or stores a key. A failed integrity check is listed as not intact and refused with 409.
- `POST /api/bench/resume {token}` is the independent portable path (backup file or pasted key). The server stores only a hash of the key.
- Restoring a record does not show the current bench is unchanged or safe: BENCH STATE stays UNKNOWN and SAFETY CLEARANCE stays NO. See docs/SAVED_SESSIONS.md.
